# Codex 控制台使用指南

这个软件在你的电脑上调用 Codex CLI，对本地 Git 仓库执行分析、审查或修改任务，并集中显示进度、审批请求和用量。

## 1. 启动和更新

在控制台项目目录中运行：

```bash
npm run open
```

也可以在 Mac 上双击 `Start-Control-Plane.command`。浏览器模式不需要安装 Electron；Node.js 20+、Git 和 Codex CLI 需要可用。启动器会打开本地控制台，默认地址是 `http://127.0.0.1:4310`。

通过终端启动的新执行器需要保持该终端打开。要退出，在启动它的终端按 **Ctrl+C**。Ctrl+Z 会暂停进程并继续占用端口。桌面应用可以从托盘菜单“退出”；若菜单显示“退出窗口（保留执行器）”，需要到原服务的启动终端退出执行器。

升级到中文版本时，先正常退出原执行器，再运行：

```bash
git pull --ff-only
npm run open
```

刷新浏览器页面；若出现“控制台更新已就绪”，点击“重新加载”。需要重启执行器，新的内置模板和版本号才会生效。

## 2. 检查环境并登录

打开“环境检查”，查看 Git、Codex CLI、登录状态和任务数据目录是否正常。找不到工具时，先安装工具，或在“配置程序路径”中填写可执行文件的绝对路径；留空会自动查找。

回到首页，点击“使用 ChatGPT 登录”，在打开的官方浏览器页面中完成授权。返回后，状态会更新为“已登录”。如果浏览器未自动打开，点击“打开登录页面”。也可以在终端运行 `codex login`，再回来点击“检查登录”。已有的 Codex 登录通常会直接被识别，控制台不会要求你填写账号密码。

“已登录”表示本地凭据可用，实际服务访问和配额会在运行任务时检查。若正在执行或排队的任务阻止登录，先完成或取消这些任务。

## 3. 添加要操作的项目

进入“项目与模板” → “添加项目”，填写项目名称和**本机 Git 仓库文件夹的绝对路径**。这里填的是你想让 Codex 检查或修改的代码项目，不是 GitHub 网页链接。

例如：`/Users/你的用户名/Projects/my-project`。不确定路径时，在目标项目的终端中运行 `pwd`。仓库必须已经使用 Git，并至少有一次提交。新建任务前先提交或妥善保存已有修改；控制台需要从干净的仓库建立隔离工作区。

移除项目登记只删除控制台的登记记录，磁盘上的仓库会保留。

## 4. 第一次使用：只读审查

1. 点击“新建任务”，选择刚添加的项目。
2. 选择“代码审查”模板，任务模式会自动设为“只读审查”。
3. 填写任务说明，例如：

   > 检查这个项目的目录结构、启动方法和可能影响运行的问题。请用中文给我一份报告，列出有依据的发现和建议，不要修改文件。

4. 点击“开始审查”。
5. 点击任务卡片的“查看进度”或“查看详情”，在“事件”中看实时进度，在“输出”中阅读完成后的报告。

在“输出”的“执行记录”中可切换每次分析、实施或重试的报告；默认自动跟随最新执行。失败和取消的记录也会保留已有内容，有错误时展开“诊断信息”查看。

只读审查不会进入写入审批或应用补丁的流程。“暂停显示”只冻结当前日志画面，任务仍在继续运行；点击“恢复显示”或“跳到最新”即可继续查看。正在运行的任务可以通过“取消任务”停止。

## 5. 让 Codex 修改代码

新建任务时选择“功能实现”“问题诊断与修复”模板，或不使用模板，任务模式选择“先分析，审批后实施”。任务说明尽量写清楚目标、允许修改的范围和完成标准。例如：

> 在 README.md 中补充“快速开始”说明，写明项目已有的安装、启动和测试命令。只修改 README.md，完成后用中文说明新增内容。

此模式有两次审批：

| 阶段 | 你需要做什么 | 结果 |
| --- | --- | --- |
| 只读分析完成 | 点击“阅读方案并审批”，在“输出”中阅读方案，选择“批准并执行”或“拒绝” | 批准后，Codex 才能在隔离工作区修改文件 |
| 隔离实施完成 | 点击“检查代码变更”，逐行查看补丁，选择“应用到原仓库”或“丢弃变更” | 应用会写回原仓库；丢弃会清理隔离变更 |

应用之前可以点击“检查是否可应用”。这会检查原仓库是否发生变化以及补丁是否适用，不修改文件；检查通过后仍需你点击“应用到原仓库”，届时会再次验证。

如果实施没有产生变更，任务会直接完成，不会出现补丁审批。“应用到原仓库”会把修改写入工作区及 Git 暂存区，**不会自动提交或推送 GitHub**。可在目标仓库运行 `git diff --cached` 检查，再按自己的工作流程提交、推送。

任务执行期间，原仓库如果切换了分支、产生新提交或文件修改，应用补丁可能被阻止。请先检查差异；需要时丢弃这次隔离变更并重新创建任务。

## 6. 查看用量和处理失败

- “用量统计”显示输入、缓存输入、输出 Token 和 Codex 执行时长；不把 ChatGPT 订阅用量直接换算成 API 美元费用。
- “设置”可调整最大并发数、单任务 Token 上限、单仓库累计配额。Token 上限填 `0` 表示不限制；预算在审批、重试和启动时检查，运行中随事件报告用量检查；保存新上限也会检查排队和执行中的任务。重试累计同一任务的用量，未提高已耗尽的上限时不会再次启动。运行事件可能在一次调用结束后才报告用量，因此实际消耗可能超过设定值。
- 任务失败或因预算停止时，先在“概览”和“事件”中查看原因，解决后点击“重试任务”。重试会按当前阶段进行，并清理隔离工作区的残留修改。
- 已结束的任务可以归档、恢复或删除历史记录。删除记录时会清理残留隔离工作区，原仓库保留。

任务说明、报告、代码补丁和原始工具消息保持原内容；未知的 Git 或系统错误可能仍显示英文，方便准确排查。

## 7. 查找任务、复用和导出

- 搜索栏支持任务内容、项目名称、仓库路径和任务 ID；多个词用空格分隔，结果需同时匹配。用“待处理优先”排序，可先看到待审批、失败和预算超限任务。筛选与排序会保存在当前浏览器，点击“清除筛选”可回到全部未归档任务；排序仍使用你的选择。
- 在项目卡片点击“新建任务”会预选该项目；“查看任务”会筛选这个项目的任务记录。
- 已结束任务的详情底部有“复用任务”。它会打开可编辑的创建表单，保留任务模式；检查项目与说明后，再点击开始。若已有草稿，会先询问是否替换。原项目登记已移除时，请先重新添加相同仓库。
- “输出”中的“下载报告”保存当前选择的执行报告（Markdown）；“代码变更”中的“下载补丁”保存原始 patch。下载本身不会应用修改。
- 用量表点击任务名可打开详情；“再显示 30 条”只改变可见明细数量，统计总量始终包含全部现存任务记录。
- 页面连接中断时会自动重连，也可点击“立即重连”。原始数据仍由执行器保存；恢复连接后会重新获取当前任务状态。正在编辑的任务草稿与设置不会被后台刷新覆盖。

## 8. 运行时间、保存与中断恢复

任务卡片和详情中的计时会在连接正常时每秒更新；等待审批和排队不增加执行时长。长时间没有新事件仅显示提示，不会据此自动取消任务。取消后出现“正在停止并清理”时，请等待结束再重试或删除。

执行中每 5 秒保存一次进度。控制台异常退出后，重启会保留最近保存的报告、诊断和耗时，并将未结束的执行标为意外中断。确认原有进程已结束、查看错误并解决问题后，再手动重试；不会把离线时间计为执行时长。

每个任务保留最近 20 次执行记录。新记录的报告最多保存前 262,144 个字符，诊断最多保存末尾 32,768 个字符；超出时会标注截断。旧记录清出此列表不减少累计用量。未完成的消息可能只在事件中出现；异常退出后，最后一次保存之后的新内容可能丢失。

## 启动仍然报端口超时

运行：

```bash
npm run status
```

它只读取健康状态和占用进程信息，不会终止任务。把输出提供给维护者继续排查。如果显示状态 `T`，按报告提示在原终端找到对应作业并恢复或正常退出。
